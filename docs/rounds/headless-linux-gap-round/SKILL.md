# 헤드리스 리눅스 제한 개선 회차

한 번의 실행에서 0~9절을 끝까지 완료한다. 백로그는 저장소의 `docs/headless-linux-gaps.md`
한 파일이고, 회차는 거기서 **상태가 `대기`인 항목 1건**만 처리한다. 다른 무인 회차
(리팩토링·QA·공개화)와 같은 저장소에서 동시에 돌며, 충돌하지 않는 이유는 레인과 항목 점유다.

무인으로 돌고 응답은 마지막 턴 출력으로만 회수되므로 **9절 보고를 반드시 남긴다.**

## 문진에서 정한 것 (2026-10-10, 설계 시 추천값으로 채움 — 사용자가 바꾸면 여기도 고친다)

| 묶음 | 값 |
| --- | --- |
| 병렬 | 켬. 레인 풀 `G01`~`G05`, 동시 기동 건수는 페이싱 탭에서 정한다(추천 3) |
| 품질 관문 | **코드리뷰 켬**(5절). 보안 불변식 G1~G11·C 예외를 건드리는 변경은 리뷰에서 `security` 결함이 0이어야 push |
| 반영 정책 | 레인 브랜치 커밋 → rebase → `private/dev-history`에 push. `origin`은 금지. 되돌림은 하지 않고 레인 브랜치에 남긴다 |
| 멈춤 조건 | `대기` 항목이 없거나 재배포 후 검증만 남으면 8절 반납 뒤 8-1절 최종 반영 조건을 확인한다. 같은 항목이 3회 연속 미착지면 그 항목을 `보류`로 적어 보고의 `decisions`에 올린다 |
| 비용 상한 | 회차당 상한 없음(페이싱이 창 %p로 조절). 변경 파일 10개 이내로 끊는다 |
| 사람이 정할 자리 | D1~D4(목록 문서 상단), AGENTS.md 2·3절 경계 이동, `Cargo.toml`·`package.json` 의존성, 사용자 문서(README). 운영 NAS 재생성·기동은 전체 회차 종료 후 허용(8-1절) |

## 금지 — 주 워크트리에서 작업하지 않는다

시작 위치(주 워크트리, 아래 `MAIN`)는 사용자와 QA 회차의 작업장이다.
**거기서 파일을 고치거나 커밋하지 않는다.** 레인이나 워크트리를 얻지 못하면 아무것도 하지
않고 그 사실만 보고하고 끝낸다. 주 워크트리에서 허용되는 명령은 `agent-manager-refactor-round`
스킬과 같다 — `fetch private`, 6-1의 조건부 push, 6-2의 조건부 `merge --ff-only`.

## 운영 NAS — 개별 회차는 조회, 전체 회차 종료 후 재생성·기동

개별 회차는 NAS(SSH 애드온에서 에이전트 사용을 켠 운영 NAS 키 — `ssh list`로 접속 정보를 읽는다)를 **읽기 명령과
브라우저 조회**로만 실측한다. 이미지 반영·컨테이너 재생성·기동은 아래 8-1절의 최종 반영에서만 한다.
새 이미지가 필요한 검증은 완료로 쓰지 않고 보고의 `next`에 "전체 회차 종료 후 재생성·기동하여 재검증"으로 남긴다.
운영 NAS 최종 반영은 **전체 회차가 끝난 뒤 컨테이너를 재생성하고 실행하도록 사용자가 허용했다**
(2026-10-11). 개별 항목 착지마다 재배포하지 않는다. 비밀값은 보지도 옮기지도 않는다(`chat-secrets` 규칙).

## 용어와 경로

```
MAIN=<주 워크트리 경로>        # 회차를 등록한 저장소의 projectPath
POOL=$MAIN/.rounds
WT=$POOL/wt-<레인>              # 레인 G01~G05

```

### D4 예외 — 이 회차만은 private 개발선에 push한다

AGENTS.md D4는 push를 금하지만 이 회차는 6절에서 `private/dev-history`에 민다. 허용되는 것은
`private dev-history` 하나뿐이고 공개 `origin`은 어떤 경우에도 건드리지 않는다.

## 0. 레인 점유 — 못 잡으면 아무것도 하지 않는다

`$POOL/.lease/nas-deploy`가 있으면 최종 반영 중이므로 새 회차를 시작하지 않고 보고한다.

`agent-manager-refactor-round` 0절과 같은 블록을 쓰되 `LANES="G01 G02 G03 G04 G05"`로 바꾼다.
`NO-FREE-LANE`이면 작업을 시작하지 말고 점유·차단 목록과 함께 보고하고 끝낸다. 긴 빌드 전에는
`touch "$POOL/.lease/lane-$LANE"`로 살아 있다는 표시를 남긴다. 레인 점유 직후에도 `nas-deploy` 락을
다시 확인하고, 생겼으면 내 레인을 반납하고 종료한다.

## 2. 항목 1건 점유

```sh
cd "$WT"
grep -n -E '^\| (H|L)[0-9]+ \|' "$LIST" | grep '| 대기 |'      # 후보
find "$POOL/.lease" -maxdepth 1 -type d -name 'gap-*' -mmin +240 -exec rm -rf {} + 2>/dev/null
# 후보를 P1→P2→P3, 같은 P 안에서는 ID 순으로 보되 시작 지점을 레인 번호로 돌려 같은 항목에 몰리지 않게 한다.
mkdir "$POOL/.lease/gap-$ID" 2>/dev/null && echo "CLAIMED=$ID" || echo "TAKEN=$ID"
```

- `TAKEN`이면 다음 후보로 간다. 전부 `TAKEN`이면 진행 중인 회차가 있으므로 재배포하지 않고 8절로 간다. 후보가 없거나 재배포 후 검증만 남으면 8절 반납 뒤 8-1절 조건을 확인한다.
- `결정대기`·`보류`·`해당없음`·`진행(…)`·`완료(…)`는 고르지 않는다.
- 후보는 **반드시 `$WT`(레인 워크트리, 개발선 기준)의 `$LIST`에서 고른다.** 주 워크트리의 사본은 보지 않는다 —
  뒤처지거나 앞서 있어 네 회차 연속 중복 착수를 만들었다(2026-10-11).
- `$POOL/reserved-paths`(형식·3일 규칙은 리팩토링 회차 2절과 같다)에 걸리는 파일을 고쳐야만 성립하는
  항목은 건너뛰고 보고에 "예약 경로로 건너뜀"으로 적는다. **단, `$LIST`의 상태 칸 한 줄을 바꾸는 것은
  예약 면제다**(2026-10-11 결정). 그 파일이 예약돼 있어도 상태 칸은 쓰고 커밋한다.
- 항목을 잡았으면 `$LIST`의 그 행 상태 칸을 `진행(<레인>)`으로 바꿔 둔다(작업 중 표시, 커밋 전까지만).
  6절 커밋 직전에 같은 칸을 `완료(<레인> YYYY-MM-DD)`로 바꿔 **본 커밋에 함께 넣는다.** 커밋 해시는
  커밋 뒤에야 알 수 있으므로 표에는 적지 않고 9절 보고와 `record_round_report`의 `commits`에 남긴다.
  `검증` 종류로 코드 변경이 없으면 상태 칸 한 줄만 바뀐 커밋이 되며, 그래도 커밋한다(검증 결과는 본문에).
- 선택한 항목의 **수용 기준을 먼저 응답에 적고** 그 기준만 만족시키는 범위로 일한다.

종류별로 하는 일:

- `개선` — 코드를 고친다. 수용 기준의 각 문장에 대응하는 테스트를 같이 둔다(AGENTS.md C16-4·C16-6의
  "argv를 실제로 받은 테스트" 원칙). 보안 경계(G·C)를 옮겨야 성립하면 **하지 않고** `decisions`로 넘긴다.
- `검증` — NAS에서 읽기 명령·브라우저 조회로 실측하고 결과를 보고에 적는다. 코드 결함이 드러나면 수용
  기준 안에서 고치고, 아니면 상태를 `완료(검증)`로 적는다.
- `문서화` — 화면 안내문·힌트를 고친다. 사용자 문서(README)는 고치지 않는다.

**D1(헤드리스 운영자 모드)은 로그인 게이트(C20)로 푼다**(사용자 2026-10-11). 회차는 tailnet 계정 일치 같은
별도 호스트 판정을 만들지 않는다. C20이 착지하면 사람이 H01·H02·H05·H06·H09의 수용 기준을 다시 쓴다.

**헤드리스 판정을 새로 만들어야 하는 항목**(H04·H10·H11·L08·L12)은 같은 판정 함수를 공유해야 한다.
첫 회차가 접속 정보(`/api/access`)에 `headless: bool`(서버가 `--tailscale-host`로 떴고 데스크톱 소유자가
없음)을 더하는 것부터 하고, 그 커밋이 착지하기 전에는 나머지 네 항목을 고르지 않는다. 계약 타입
변경이므로 그 첫 회차는 `types.ts`·`remote.rs` 둘을 함께 고친다.

## 3. 구현 — 변경 파일 10개 이내

파일은 필요한 범위만 읽는다(`sed -n`·`grep -n`). 테스트에서만 쓰는 항목은 `#[cfg(test)]`로 한정한다
(`cargo clippy -D warnings`가 개발선을 깨뜨린다). 동작이 같은지 확신할 수 없는 지점은 손대지 않고 보고에 남긴다.

## 4. 검증 — AGENTS.md 8절

레인 전용 빌드 디렉터리를 쓴다. 디스크 여유 40G 미만이면 빌드하지 않고 보고한다.

```sh
export CARGO_TARGET_DIR="$POOL/target/$LANE" CARGO_BUILD_JOBS=2
```

- Rust를 고쳤으면: `cargo test -q -p <crate> --lib <module>::` → `cargo clippy -q -p <crate> --all-targets -- -D warnings`(생략 금지) → `cargo fmt --all --check`
- 프런트를 고쳤으면: `npx tsc --noEmit`, `node --experimental-strip-types --test --test-reporter=dot src/lib/<파일>*.test.mjs`
- 화면 동작을 바꿨으면: `npm run build` 뒤 `node scripts/e2e.mjs --port 5600<레인 끝자리>`
- `deploy/synology/`를 고쳤으면: `docker build`는 맥의 Docker 자격증명 도우미 문제로 빈 `DOCKER_CONFIG`가 필요할 수 있다. 이미지 빌드까지 못 하면 그 사실을 보고하고 `next`에 적는다.

통과 출력은 인용하지 않고 `test result:` 줄만 보고한다. 실패가 남으면 **커밋하지 않고** 원인과 함께 보고한다.

## 5. 코드리뷰 관문 — push 전에 독립 리뷰를 받는다

커밋 전에 변경분(`git diff`)을 **이 회차와 다른 문맥의 리뷰어**가 본다.

- Claude 실행이면 `parallel-reviewer` 서브에이전트에 디프와 수용 기준·AGENTS.md 2·3절을 주고 읽기 전용
  리뷰를 받는다. Codex·Antigravity 실행이면 같은 질문을 자기 자신에게 **새 턴의 점검표**로 돌린다:
  (1) G1~G11 중 건드린 것 (2) C 예외 경계 이동 여부 (3) 원격·헤드리스 판정 우회 가능성 (4) 비밀값이
  로그·응답·파일에 남는 경로 (5) 테스트가 실제 argv·출력으로 판정을 고정하는지.
- 결과를 `correctness`·`security`·`test-coverage`·`simplification`으로 나눈다. `security`·`correctness`는
  0이 될 때까지 고치고 4절을 다시 돈다. 나머지는 고치거나 보고의 `next`에 적는다.
- 리뷰 요약(지적 수·고친 수·남긴 수)을 커밋 본문과 9절 보고에 적는다. 리뷰를 건너뛴 커밋은 push하지 않는다.

## 6. 커밋과 착지

```sh
git rev-parse --show-toplevel        # $WT 여야 한다. $MAIN 이면 커밋하지 않는다
git status --short                   # 수용 기준 밖 경로가 있으면 되돌린다
git add -A && git commit -m "헤드리스: <항목 ID> <무엇을>"
```

- 제목은 `헤드리스: `로 시작한다. 본문에 항목 ID·수용 기준·검증 명령과 `test result:` 줄·리뷰 요약·
  의도적으로 그대로 둔 것·레인 번호를 적고 `Co-Authored-By` 트레일러로 닫는다.
- 착지(push 락, rebase, `INCOMING` 겹침 재검증, 충돌 시 힘으로 풀지 않음, 주 워크트리 ff 따라가기)는
  `agent-manager-refactor-round` 6-1~6-3과 **똑같이** 한다. 락 이름도 같은 `push`를 쓴다(모든 회차가 한 락을 공유한다).

## 7. 보고 — record_round_report

`record_round_report`를 부른다. Antigravity처럼 `aia_system`이 없는 실행은 앱 데이터의
`round-report-agent-mcp.json`에 적힌 주소에 붙어 같은 이름의 작업을 부른다(`get_round_goals`·
`list_round_reports`·`record_round_report`·`update_round_goal` 넷만 열려 있다).

- `goalId`: `goal-26751b658757466dab58099921784a47`(회차 목표 카드). 빠뜨리면 보고가 화면의 회차 상세에 나오지 않는다
- `title`: `<항목 ID> <한 줄>` · `outcome`: 착지면 pass, 검증만·미착지면 partial, 되돌렸거나 막혔으면 fail
- `measures`: 목록의 `대기`/`진행`/`완료`/`결정대기` 건수 before/after
- `failureKinds`: 이 항목이 없앤 실패 종류(예: `원격 → push 거부`)와 새로 생긴 종류
- `commits`: 착지 해시 · `decisions`: D1~D4 중 이 회차가 부딪힌 것 · `next`: 다음 회차 몫

보고 전에 `list_round_reports`로 지난 회차의 `decisions`에 답이 달렸는지 읽고, 답이 났으면 그 항목의
상태를 사람이 `대기`로 바꿨는지 확인한다(회차가 바꾸지 않는다).

## 8-1. 전체 회차 종료 후 NAS 최종 반영

전체 회차 종료는 **처리 가능한 구현·문서화·검증 회차의 리뷰·커밋·착지가 끝나고 실행 중인 레인과
미착지 커밋이 없는 상태**다. 새 이미지·컨테이너가 있어야 가능한 NAS 실측은 최종 반영 뒤에 수행한다.
`결정대기`·`보류`는 전체 완료로 간주하지 않고 제외된 항목으로 보고한다. 다른 레인이 점유한 항목,
검증 실패, 미착지 커밋을 "재배포 후 검증"으로 돌려 완료 조건을 통과시키지 않는다.

1. 내 레인·항목을 반납한 뒤 최신 `private/dev-history`, G01~G05의 실행·점유 상태와 미착지 커밋,
   최신 보고를 다시 조회한다. 재배포 후 실측 이외의 대기·진행 항목이나 실행 중인 회차가 있으면 반영하지 않는다.
2. `mkdir "$POOL/.lease/nas-deploy"`로 최종 반영을 한 건만 점유한다. 점유 실패면 종료하고,
   점유 뒤에도 1번을 다시 확인한다. 모든 개별 회차는 이 락이 있으면 새 항목을 시작하지 않는다.
   같은 개발선 SHA의 성공한 최종 반영 보고가 이미 있으면 재생성을 반복하지 않는다.
3. `ssh-endpoints` 스킬로 현재 활성 연결·명령·전송 정책을 다시 조회한다. 검증·리뷰·착지를 마친
   개발선 SHA의 이미지와 배포 파일만 준비한다. 이미지 빌드 실패나 디스크 부족이면 운영 컨테이너를 바꾸지 않는다.
4. 기존 NAS 배포 위치와 compose 서비스명을 확인하고 해당 스택만 반영한다. 필요하면 검증된 이미지를
   `docker load`로 반영한 뒤 `docker compose up -d --force-recreate`로 대상 컨테이너를 재생성·기동한다.
   서버와 네트워크를 공유하는 사이드카의 관계를 유지한다. 기존 `.env`, HOME·계정·세션·키링·볼륨은
   보존하며 `down -v`·볼륨 삭제·비밀값 출력은 하지 않는다. 별도 설정 변경은 항목의 승인된 범위만 적용한다.
5. 실제 이미지 식별자와 실행 상태, tailnet HTTPS 접근, `/api/access`와 신원 헤더 인증을 확인하고,
   보고에 남긴 재배포 후 검증 항목을 수용 기준대로 실측한다. 실측되지 않은 항목은 완료로 바꾸지 않는다.
   상태 변경 커밋은 최종 반영 보고와 `nas-deploy` 락 반납 뒤 기존 레인·리뷰·착지 절차로 처리한다.
6. 성공·실패 모두 `record_round_report`에 "NAS 최종 반영" 보고를 남긴다. 개발선 SHA, 이미지 식별자,
   재생성·기동 결과, 검증 결과, 제외된 결정대기·보류 항목과 남은 일을 적고 락은 반드시 반납한다.
   실패하면 추가 재생성·자동 재시도를 멈추고 실제 운영 상태와 다음 조치를 보고한다.

## 9. 마지막 응답의 보고

레인·항목·수용 기준, 미착지 커밋 유무, `MAIN-AHEAD/BEHIND`·`INCOMING` 겹침, 예약 경로, 변경 파일,
검증 명령과 `test result:` 줄, 리뷰 요약, 커밋 해시와 push 결과, `record_round_report` 성공 여부,
레인·항목 반납 여부, NAS 최종 반영 조건·재생성·기동·재검증 결과(미실행이면 이유), 다음 회차 몫. 커밋 없이 끝난 경우에도 같은 형식으로 무엇을 확인하고 왜 멈췄는지 적는다.
