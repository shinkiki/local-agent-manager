# 로컬 LLM 공급자(`local`)

Agent Manager의 네 번째 공급자다. Claude·Codex·Antigravity와 같은 자리에 서서 채팅,
세션 탐색, 반복 요청, 워크플로, AIA에 쓰인다. 다른 셋과 다른 점은 하나뿐이다 —
**모델이 사용자가 직접 띄운 서버에서 온다.** 계정도 사용량 할당량도 없다.

이 문서는 사용자와 다음 회차를 위한 개요다. 왜 이렇게 됐는지의 실측 근거는
[ACP 하네스 실측](local-llm-acp.md)과 [Codex CLI 수동 스모크](local-llm-smoke.md)에 있고,
지켜야 할 조건은 `AGENTS.md`의 `C14`가 정본이다.

## 한눈에

| 항목 | 값 |
| --- | --- |
| 공급자 id | `local` (`ProviderId::Local`) |
| 실행 하네스 | ACP — `opencode acp` (stdio, 줄 단위 JSON-RPC 2.0) |
| 모델 출처 | 사용자가 띄운 OpenAI 호환 서버 (Ollama 등) |
| 계정 | 없음 — 등록·전환·격리 프로필 모두 해당 없음 |
| 사용량 할당량 | 없음 — 페이싱 레인·pooledAccounts에서 제외된다 |
| 연결 설정 | `<app data>/local-llm-connection-v1.json` + OS 보안 저장소의 API 키 |
| 세션 원본 | 하네스 DB (`~/.local/share/opencode/opencode.db`) |
| 자체 CLI | 없음 |

## 왜 Codex 하네스가 아닌가

처음 계획은 Codex CLI를 하네스로 재사용하는 것이었다(`docs/local-llm-smoke.md`의 작업 0.2).
실측에서 뒤집혔다. Codex는 모델에게 도구 26개를 선언하고 설정으로 6개 아래로 줄일 수
없는데, 로컬 모델은 그 수에서 도구를 부르지 못한다 — 2026-09-24 측정으로 26개일 때는
없는 이름을 지어내고, 10개일 때는 호출 대신 코드 블록을 뱉고, 3개일 때 제대로 불렀다.

그래서 ACP 하네스(`opencode acp`)로 갈아탔다. 도구 수를 우리가 정할 수 있고, 재개가
프로토콜 1급 기능이라 Codex 경로에서 rollout 파일을 뒤져 재개하던 일이 없어진다.
`opencode acp`는 Codex `app-server --stdio`와 같은 자리라 기존 자식 프로세스 배선에
그대로 얹힌다. (`C14-1`)

## 설정 파일 — 두 키만 우리 것이다

`~/.config/opencode/opencode.json`은 **사용자 소유** 파일이다. 앱이 소유하는 키는 둘뿐이다.

- `provider.agent-manager-local` — 등록한 서버 주소와 모델
- `agent.agent-manager-local*` — 묶음별 에이전트 항목

나머지 키는 읽어서 그대로 되쓰고, 파일은 원자적으로 교체한다. 연결을 끄면 두 키를
**지운다** — 꺼진 채 낡은 주소가 남아 있게 두지 않는다. (`C14-2`)

Codex의 `config.toml`처럼 앱이 실행 인자만으로 끝낼 수 있는 구조가 아니다. ACP 하네스는
공급자·에이전트 정의를 설정 파일에서 읽으므로, 파일을 건드리는 것이 이 공급자에서는
피할 수 없는 경로이고 그래서 `C14`가 예외로 적혀 있다.

## 도구 묶음 — 적게 실어야 부른다

ACP는 MCP 서버 목록을 `session/new`에서 고정한다. 세션 도중에 뺄 수 없다는 뜻이다.
그래서 묶음을 에이전트로 가른다.

| 묶음 | 여는 도구 | 닫는 도구 |
| --- | --- | --- |
| 작업 공간 (`agent-manager-local`) | `bash`, `read`, `write` | `agent-manager_*` |
| 시스템 (`agent-manager-local-system`) | `agent-manager_*` | 작업 공간 도구 전부 |

**양쪽을 다 닫아야 한다.** 한쪽만 닫으면 그 묶음은 자기 도구에 더해 시스템 MCP 전체를
들고 있게 되고, 그 개수가 이미 실패한 개수다. (`C14-3`)

묶음은 턴 전에 **사용자의 말에서** 고른다. 모델에게 묻지 않는다 — 왕복 한 번이 더 들고
모델이 틀릴 수 있다. 낱말 목록은 앱 어휘에 지금 등록된 외부 플러그인 이름을 턴마다
더해 만들고, 프리셋으로 내보내는 브랜드는 한글 표기를 별칭표에 들고 있다("노션"은 어떤
플러그인 id에도 없다). 애매하면 작업 공간 묶음에 둔다. (`C14-3a`)

## 파일 읽기·쓰기는 앱이 막는다

하네스는 파일 접근을 클라이언트에 넘긴다(`fs/read_text_file`, `fs/write_text_file`).
그래서 경계를 앱이 직접 집행한다 — 채팅의 쓰기 모드(`ChatMode::Plan`은 승인을 받아도
쓰지 않는다)와 작업 폴더 경계(채팅의 루트 밖 경로는 승인과 무관하게 거절)다.
실패는 JSON-RPC `error`로 답한다. `result` 안에 넣은 실패는 성공으로 읽혀서, 모델이
쓰지도 않은 파일을 썼다고 보고한다. (`C14-5`)

승인 등급은 ACP 권한 선택지의 `kind`에 1:1로 대응시킨다 — `optionId`로 맞추지 않는다.
`AcceptAll`은 `allow_once`로 접어서 계획 검토용 등급이 단건 요청을 넓히지 못하게 하고,
하네스가 내놓지 않은 등급은 비슷한 것으로 갈아치우지 않고 `cancelled`로 답한다. (`C14-4`)

## 세션

세션 기록은 하네스 DB에 있다. 카탈로그는 `agent` 칸이 앱의 에이전트인 세션만 가져가므로,
사용자가 자기 손으로 돌린 OpenCode 대화는 앱에 나타나지 않는다. (`C14-6`)

## 서버 주소 확인

주소 확인(probe)은 저장된 상태를 건드리지 않지만 **바깥으로 나가는 행위**라 원격
**쓰기** 관문 뒤에 있다. 읽기로 열어 두면 읽기 전용 원격 클라이언트가 호스트더러 임의의
내부 주소에 접속하게 만들 수 있다. (`C14-7`)

## 릴리스 노트 초안

> **로컬 LLM 공급자가 추가됐습니다.** 직접 띄운 OpenAI 호환 서버(Ollama 등)를 설정에
> 등록하면 Claude·Codex·Antigravity와 같은 자리에서 채팅, 반복 요청, 워크플로, AIA에
> 쓸 수 있습니다. 계정 로그인도 사용량 할당량도 없고, 대화 내용은 호스트를 떠나지
> 않습니다. 실행은 ACP 하네스(`opencode acp`)를 거치며, 로컬 모델이 도구를 제대로
> 부를 수 있도록 한 번에 실리는 도구를 대화 내용에 맞춰 최소한으로 줄여 보냅니다.
