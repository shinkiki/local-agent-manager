# 에이전트 다중 계정·사용량 개선 계획

- 상태: Codex·Claude 구현 / Antigravity 계획
- 작성일: 2026-08-12 (개정 2026-09-17: 8절 Antigravity 추가)
- 대상: Agent Manager Tauri
- 지원 공급자: OpenAI Codex, Claude Code, Google Antigravity(8절)
- 참고 구현: [stablyai/orca](https://github.com/stablyai/orca)

## 1. 확정 원칙

- Codex와 Claude는 기존 공유 `CODEX_HOME`·`CLAUDE_CONFIG_DIR`을 유지한다.
- Antigravity는 자격증명만 가르는 환경변수가 없어 `HOME`을 가른다(8절). 이 공급자에만 적용하며, Codex·Claude가 쓰는 공유 함수의 시그니처·상수 목록은 넓히지 않는다.
- 공급자 session ID와 히스토리는 계정과 분리해 그대로 재개한다.
- 인증 비밀은 OS 보안 저장소에만 장기 보관한다.
- macOS에서는 모든 계정 비밀을 버전형 단일 Keychain Vault 항목에 보관해 앱 접근 승인을 항목 하나로 제한한다.
- 공급자 런타임이 없을 때만 Core의 credential adapter가 공유 홈의 인증 항목을 원자 교체한다.
- 공급자 세션·히스토리·설정·플러그인·SQLite·JSONL은 편집, 복사, 링크하지 않는다.
- 계정 변경 작업은 로컬 데스크톱 전용이다. 원격에서는 계정 목록과 사용량만 조회한다.

## 2. 계정 모델과 동작

`ProviderAccountView`는 계정 ID, 공급자, 표시명, 이메일·조직, 인증 상태, 활성·기본·비활성·전환 대기 상태와 계정 한도 사용량을 제공한다.

공급자별 상태는 다음 세 값을 분리한다.

- `defaultAccountId`: 사용자가 선택한 기본 계정
- `activeAccountId`: 공유 인증 홈에 실제 적용된 계정
- `pendingDefaultAccountId`: 실행 종료 후 적용할 기본 계정

지원 동작은 `계정 추가`, `기본 계정으로 선택`, `재인증`, `비활성화`, `삭제`다. 추가·재인증은 격리된 임시 프로필에서 공식 CLI 로그인을 실행하고 결과 인증만 OS 보안 저장소에 등록한 뒤 임시 프로필을 제거한다. 삭제는 활성·기본·전환 대기 계정, 연결된 반복 요청 또는 런타임이 없는 경우에만 Agent Manager 등록정보·보안 저장소 자격증명·사용량 캐시를 제거한다. 공유 공급자 홈의 히스토리는 삭제하지 않는다.

**미해소 간극(2026-09-17 확인).** 자격증명 격리가 들어온 뒤 Codex의 대화 본문(rollout JSONL)이 계정 프로필 안에 쌓이고, 계정 삭제는 프로필 디렉터리를 통째로 지운다. 세션 목록은 공유 `state_5.sqlite`에 남아 사라지지 않지만 본문은 사라진다. 아직 관측된 적은 없다 — 삭제된 계정이 0건이다. 삭제 시 대화 본문 보존 여부를 확인받는 절차로 좁힌다(8절 M6).

## 3. 인증 전환 안전성

- 인증 교체와 런타임 획득은 공급자 단위 배타 잠금을 공유한다.
- 잠금 안에서 런타임 0건과 외부 공급자 프로세스 부재를 다시 확인한다.
- 인증 교체 후 계정 신원을 검증한 뒤에만 `activeAccountId`를 변경한다.
- 전환 journal에는 이전 활성 계정, 실행 계정, 전환 ID와 단계만 저장한다.
- 앱 시작 시 journal이 남아 있으면 이전 활성 계정 복원을 우선하고, 복구 전까지 해당 공급자 실행을 차단한다.
- 비밀은 로그·오류·직렬화·IPC·원격 API에 포함하지 않는다. 사용량 조회도 자격증명을 임시 디스크에 쓰지 않고 Core 메모리에서만 사용한다.
- 단일 Vault 갱신은 프로세스·파일 잠금으로 직렬화하고, 손상·미지원 버전·저장 실패 시 기존 문서를 덮어쓰지 않는다.
- 로컬 macOS 개발 바이너리는 고정 자체 서명 인증서와 `com.shinc.agentmanager` 식별자로 실행한다. 인증서가 없거나 검증이 실패하면 미서명 실행으로 대체하지 않는다.

## 4. 반복 요청

`ScheduledRequestInput`은 필수 `accountId`를 저장한다. `ScheduleRun`은 요청 계정, 실제 실행 계정과 `waitingForAccount` 상태를 기록한다.

반복 실행은 계정을 전환하지 않는다. 자격증명 격리가 들어온 뒤로 비활성 계정도 자기 프로필로 바로 실행되므로, 전환은 공유 CLI 홈의 로그인 계정을 앱 밖까지 바꾸고 복원 동안 다른 실행을 멈춰 세우는 비용만 남았다. 전환 상태로 남은 예전 실행을 복구하는 경로(`previousActiveAccountId`·`accountSwitched`·`transitionId`)는 그대로 두고, 새 실행에서는 채우지 않는다.

실행 규칙은 다음과 같다.

1. 요청 계정이 활성 계정이면 공유 홈 자격증명으로 즉시 실행한다.
2. 다른 계정이면 그 계정의 자격증명 프로필을 준비해 격리로 실행한다.
3. Antigravity는 활성 계정만 공유 홈(실 `HOME`)으로 실행하고, 그 외 계정은 프로필 `HOME`으로 실행한다(8절 D1).
4. 격리를 준비하지 못하면 공유 홈으로 되돌리지 않고 `계정 준비 대기` 상태로 남는다. 격리 실패 판정은 재시도 시각까지만 캐시하므로, CLI 경로나 저장소 권한을 고치면 앱 재시작 없이 회복된다.
5. 같은 반복 요청이 다시 도래하면 기존 보류 실행 하나로 합친다.
6. 동일 대화 이어가기는 공유 히스토리의 기존 provider session ID를 그대로 사용한다. Antigravity는 공유 히스토리가 없으므로 세션을 마지막 실행 계정에 결속한다(8절 D4).

## 5. UI와 사용량

- 반복 요청 편집기에서 공급자 다음에 필수 `실행 계정`을 제공한다.
- 반복 요청 카드에는 계정명을 표시하고, 실행 이력에는 대기 사유와 예전 실행의 전환 복원 정보를 표시한다.
- 설정 공급자 카드에서 계정별 상태·사용량과 다섯 가지 계정 동작을 제공한다.
- 좌측 `CLI 연결 상태` 카드에는 Codex·Claude 활성 계정의 최대 사용률, 가장 가까운 초기화 시각과 조회 오류를 표시한다.
- 계정 한도 사용량은 계정별로 캐시하며 세션 토큰 집계와 분리한다.
- 사용량 조회는 별도 비동기 IPC로 실행해 계정 전환이나 채팅 시작을 차단하지 않는다.

## 6. 구버전 Agent Manager 데이터 정리

신규 저장소 최초 시작 시 supervisor 생성 전에 다음 Agent Manager 소유 파일만 한 번 제거한다.

- `scheduled-requests.json`
- `session-catalog-v1.json`
- `session-supplements.json`

새 저장소는 v2 파일명으로 빈 상태에서 시작한다. 구버전 serde 호환, 계정 backfill, system 계정 변환은 구현하지 않는다. 즐겨찾기·폴더·문서 루트, 원격접속, 언어·테마·번역 설정은 유지하며 `~/.codex`, `~/.claude`와 모든 공급자 인증·히스토리는 정리 대상이 아니다.

## 8. Antigravity 계정 격리 (2026-09-17 추가)

상세 계획은 노션 [Antigravity 계정 격리 개발 계획 — HOME 프로필 + 세션 귀속](https://app.notion.com/p/3dd257f3dd7281059099cc581c2234cc)에 둔다. 이 절은 이 문서의 원칙과 달라지는 지점만 적는다.

### 8.1 왜 홈을 가르는가

Antigravity CLI(`agy`)에는 자격증명 저장소만 옮기는 환경변수도, 실행 단위 플래그도 없다. 토큰 위치는 `HOME` 하나가 정한다. 실측으로 확인한 사실은 다음과 같다.

- 빈 홈에 `.gemini/antigravity-cli/antigravity-oauth-token`과 `.gemini/jetski-standalone-oauth-token` 두 개만 실파일로 두면 그 계정으로 정상 동작한다.
- `refresh_token`은 회전하지 않는다. 갱신되는 값은 access token·id token·만료뿐이라 복사본이 서로를 무효화하지 않는다.
- 토큰 파일은 원자적 rename으로 교체되므로 심링크로 걸 수 없다. 디렉터리 심링크는 안전하다.
- 없는 대화 ID로 이어가기를 요구해도 실패하지 않는다. 경고 한 줄 뒤 새 대화를 만들고 성공으로 끝낸다.

### 8.2 확정 사항

- **D1 모든 계정이 자기 프로필(2026-09-18 개정).** 활성 계정도 예외가 아니다. 활성 계정만 공유 홈을 쓰게 두면 기존 대화를 보존하는 것처럼 보이지만, `set_active`는 레지스트리만 고칠 뿐 공유 홈의 로그인을 바꾸지 않아 둘이 어긋난다 — 계정 카드가 남의 잔량을 보여 주고 실행도 그 쿼터를 쓴다(실측). 공유 홈에 이미 있는 대화는 D3a로 잇는다.
- **D2 배치.** 토큰 두 개만 프로필 소유 실파일(0600)이고, `.gemini/config`·`.gitconfig`·`.ssh`는 공유 홈으로 디렉터리 심링크한다. 대화·brain·로그는 프로필 소유다.
- **D3 대화 비공유.** 대화 디렉터리를 공유하면 격리 CLI가 다른 계정 대화 DB를 전부 열고 sqlite 사이드카를 만든다. 공유하지 않고 카탈로그가 프로필 홈까지 훑는다.
- **D3a 대화 하나씩 잇기(2026-09-18 추가).** 다른 홈에 있는 대화를 이어갈 때는 **그 대화 하나만** 실행 계정 프로필로 심링크한다. 원본은 제자리에 남고 이어지는 턴도 거기 쌓이며, 파일에 쓰는 주체는 공급자 공식 CLI다(G3). 사본을 만들지 않아 목록에 같은 대화가 둘로 보이지 않는다. 실측: 다른 계정에서 이어가도 대화 ID가 유지되고 문맥이 이어지며 링크가 살아남는다.
- **D4 세션 결속.** Antigravity에는 Claude의 공유 설정 디렉터리나 Codex의 공유 스레드 저장소에 해당하는 공유 색인이 없다. 세션은 `ResumeAccountPolicy`와 무관하게 마지막 실행 계정에 결속하고, 그 계정을 쓸 수 없으면 이어가기를 거부한다.
- **D5 `HOME`은 공용 목록에 넣지 않는다.** `CREDENTIAL_ENV_KEYS`에 넣으면 `strip_inherited_credential_env`가 무관한 자식의 홈을 지우고, `is_restricted_doc_root`가 홈 전체를 문서 금지 경계로 만든다. 주입은 런타임 환경 전용 통로로 낸다.
- **D6 규칙 선행.** `AGENTS.md` C4는 "홈 전체를 나누면 세션 색인이 깨지므로 자격증명만 가른다"를 전제로 쓰여 있었다. 홈을 가르는 예외 `C12`(HOME 격리 프로필 어댑터)를 신설했고, 위 D1~D5는 각각 `C12-5`·`C12-3`/`C12-4`·`C12-4`·`C12-8`·`C12-6`으로 조건화되어 있다. 구현은 그 조건을 만족해야 완료로 본다.

### 8.3 Codex·Claude 회귀 방지

변경은 Antigravity 전용 경로로만 들어간다. 공유 함수의 시그니처·정리 스펙·상수 목록은 넓히지 않는다.

- 카탈로그의 다중 홈 스캔은 Antigravity 리스터에만 준다. Codex는 `threads.rollout_path`가 프로필 절대경로를 담고 있어 이미 목록·본문이 모두 정상이므로 손대지 않는다. Codex 지문은 파일 두 개뿐이라 프로필 세션을 넣으면 비용만 커진다.
- 대화 ID 불일치 방어선은 Antigravity의 명시적 이어가기 요청에만 적용한다.
- `manages_accounts()`를 켜면 반복 요청이 계정을 필수로 요구한다. 계정 없이 저장된 기존 Antigravity 반복 요청과 페이싱 항목에 마이그레이션이 필요하다.
- 정리 루트(`C11`)는 확장자 하나로 전 공급자를 묶고 있다. 공급자별 스펙으로 나눈 뒤 Antigravity에만 대화 DB 확장자를 등록한다.
