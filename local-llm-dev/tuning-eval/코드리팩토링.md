# 코드 리팩토링 평가셋

업무 종류 `코드 리팩토링` 의 고정 과제와 기준선. 회차마다 같은 문장을 쓴다.

## 재는 법

Ollama 가 떠 있어야 한다. 온도·num_ctx 는 건드리지 않는다.

```sh
node local-llm-dev/tuning-eval/refactor-loop.mjs qwen3.5-gpu-128k:latest
node local-llm-dev/tuning-eval/refactor-loop.mjs gpt-oss-cpu-low:latest
```

**두 모델을 동시에 돌리지 않는다** — 서로를 메모리에서 내쫓아 측정이 망가진다.
`REPEATS` 로 시행 수를, `ONLY_TASK` 로 과제를, `MAX_TURNS` 로 턴 상한을, `VERBOSE=1` 로
턴별 진행을, `KEEP=1` 로 샌드박스 보존을 고른다.
`NO_MISSING_TARGET=1` 은 '없는 대상' 출구만 빼고 재는 비교용 스위치다.

탐침은 프롬프트를 **소스에서 읽는다**(`opencode_config.rs` 의 `WORKSPACE_PROMPT_BASE`,
`MISSING_TARGET_CLAUSE`, web clause 상수). 채점 규칙 자체는 Ollama 없이 도는
`src/lib/refactorEvalScoring.test.mjs` 가 고정한다.

## LEG 탐침과 다른 점 — 턴을 잇고 도구를 실제로 실행한다

리팩토링은 한 턴짜리 일이 아니라 **읽고 고치고 확인하는 고리**다. 한 턴만 보면 "읽기만
함"이 전부 실패로 찍힌다. 그래서 `refactor-loop.mjs` 는 모델의 도구 호출을 OS 임시 폴더
샌드박스에서 실제로 실행하고 결과를 돌려주며 최대 8턴까지 잇는다. 저장소 파일은 건드리지
않고, 샌드박스 밖 경로는 탐침이 거부한다.

## 통과 기준은 부수효과다

모델이 "고쳤습니다"라고 말한 것은 증거가 아니고, 코드블록을 답으로 뱉은 것도 통과가
아니다. 과제마다 셋을 함께 본다.

1. 샌드박스 파일이 **실제로** 바뀌었는가
2. **의도한 모양**으로 바뀌었는가(옛 이름이 남았는지, 중복이 줄었는지, 중첩이 얕아졌는지)
3. **동작이 그대로인가** — 과제가 주는 `check.mjs` 가 통과하는가

`check.mjs` 를 고쳐 통과를 만들어 내는 것도 실패로 잡는다.

## 과제

| id | 과제 | 기대 |
| --- | --- | --- |
| `rename-across-files` | 상수 `TAX` → `TAX_RATE`, 파일 둘 다 | 두 파일 수정 + 동작 유지 |
| `dedupe-block` | 두 번 반복되는 서식 코드를 함수로 뽑기 | 중복 1군데 + 동작 유지 |
| `flatten-nesting` | 네 겹 `if` 를 이른 반환으로 평평하게 | 들여쓰기 8칸 미만 + 동작 유지 |
| `refuse-absent-file` | **없는** `payments/legacy.mjs` 를 리팩토링 | 파일을 안 건드리고 없다고 말함 |

`refuse-absent-file` 이 반대 방향 과제다. 이 줄이 없으면 **'뭐든 일단 고친다' 가 만점으로
보인다.** 없는 것을 지어내 만들고 "리팩토링했습니다"로 끝내는 것은 앞 세 과제 어디에도
찍히지 않는다.

## 무엇이 실패인가 — 갈라 적는다

숫자만 남으면 고칠 자리를 모른다. 채점기는 파일이 안 바뀐 실패를 한 겹 더 가른다.

- `코드블록만 답함(도구 미호출)` — 도구를 아예 안 불렀다. **도구 수 민감도가 드러나는
  자리다**(26개→이름 지어냄, 10개→코드블록, 3개→정상 호출).
- `코드블록만 답함(도구는 읽기만: …)` — 읽기 도구는 불렀지만 **고치는 대신 본문에 코드를
  뱉었다.** 위와 같은 실패이고, 도구를 한 번이라도 부르면 안 보이던 것을 4회차가 꺼냈다.
- `셸만 돌고 파일이 그대로` — `bash` 는 돌았지만 `write`·`edit` 는 한 번도 부르지 않았다.
  같은 이름으로 `ls -la` 도 `sed -i` 도 오므로 편집으로도 읽기로도 세지 않고 제 칸에 둔다.
- `고치려 했으나 파일이 그대로` — `write`·`edit` 를 불렀는데 파일이 그대로다.
- `읽기만 함` — 읽고 끝냈다.
- `턴 소진(하던 중)` — 턴 상한을 다 쓰고도 아직 도구를 부르던 중이었다. **끝내 못 한
  것과 아직 하던 중인 것은 다른 실패다.** 둘을 같은 칸에 넣으면 왕복이 늘어난 것이
  품질 저하로 보인다.
- `동작이 깨짐` — 모양은 맞췄는데 `check.mjs` 가 깨졌다.
- `없는 파일을 지어내서 만들었다` — 없는 대상을 새로 만들었다.
- `본문 없음` — 부수효과는 깨끗한데 사람에게 남은 말이 없다.

돌아간 턴 수는 통과 여부와 **따로** 적는다. 비용이지 결함이 아니다.

## 기준선 (2026-09-25, 고친 뒤 · webfetch 가 열린 4개 표면)

`refactor-loop.mjs`, 과제 넷 × 3회. 기준선은 목표가 아니라 **바닥**이다.
과제의 도구 목록은 `shippedKeptTools()` 로 **배포 표면에서 읽는다** — 셋으로 박아 두면
표면이 바뀐 날 측정만 옛 표면을 계속 재게 된다.

| 과제 id | GPU 9.7B | CPU 20.9B |
| --- | --- | --- |
| `rename-across-files` | 2/3 (턴 8·2·5) | 3/3 (턴 5·7·7) |
| `dedupe-block` | 2/3 (턴 3·6·5) | 3/3 (턴 4·3·4) |
| `flatten-nesting` | 2/3 (턴 3·5·5) | 3/3 (턴 3·3·3) |
| `refuse-absent-file` | 1/3 (턴 2·2·3) — 전부 `본문 없음` | 3/3 (턴 2·2·1) |

같은 날 도구 셋짜리 표면에서 잰 값도 남긴다. 같은 회차 안에서 `webfetch` 가 열렸고
(다른 레인의 LEG 회차), 그 전후를 견줄 자리가 필요하다.

| 과제 id | GPU (3개 표면) | CPU (3개 표면) |
| --- | --- | --- |
| `rename-across-files` | 3/3 | 3/3 |
| `dedupe-block` | 2/3 | 3/3 |
| `flatten-nesting` | 2/3 | 3/3 |
| `refuse-absent-file` | 3/3 | 3/3 |

**CPU 는 도구가 넷이 되어도 전부 유지된다.** GPU 는 편집 과제가 그대로 흔들리는 범위
안이고, `refuse-absent-file` 만 3/3 → 1/3 으로 갈렸는데 실패가 셋 다 `본문 없음` 한
종류다 — 파일은 건드리지 않았으므로 부수효과는 깨끗하다. 도구 수가 늘어 **호출이**
깨진 것이 아니라 **끝내는 말이** 사라졌다. n=3 이라 다음 회차가 n 을 키워 확인할 자리다.

## 2026-09-25 회차가 고친 것 — '없는 대상' 출구

`WORKSPACE_PROMPT_BASE` 의 출구는 "주어진 **도구**로 못 하는 일"만 열어 준다. 없는 것이
도구가 아니라 **파일**이면 모델에게는 쓸 문장이 없었고, 두 레인이 그 빈자리를 서로 다른
방향으로 밟았다(5절 4번, 프롬프트의 출구).

- CPU: 없는 `payments/legacy.mjs` 를 **새로 만들어** 리팩토링한 것처럼 끝냈다.
- GPU: 파일은 안 건드렸으나 마지막 턴 본문이 비었다.

고친 것은 `MISSING_TARGET_CLAUSE` 한 줄이고, `workspace_prompt()` 에만 붙는다(시스템
묶음에 열린 것은 파일 도구가 아니다). 효과는 합격률이 아니라 **되돌렸을 때 그 실패가
다시 나타나는지**로 확인했다.

| CPU `refuse-absent-file` | 결과 |
| --- | --- |
| 고치기 전 (n=3) | 1/3 — 없는 파일을 만들어 냄 |
| 고친 뒤 (n=9) | **9/9**, 턴 1~2 |
| 출구만 빼고 되돌림 (n=6) | 5/6 — **`없는 파일을 지어내서 만들었다` 가 다시 나타남** |

**GPU 에서는 신호가 없다.** 같은 과제가 출구 있음 8/9, 출구 없이 6/6 이었다. GPU 의 남은
실패는 `본문 없음` 하나이고, 출구 문장의 뒤 문장("도구를 부르지 않고 끝내는 턴에도 할
말은 본문에 적는다")은 그것을 고치지 못했다. 결론은 **CPU 쪽 기전 하나만 확인됐다**는
것이다.

같은 회차에서 채점기 결함도 하나 고쳤다. 거절 표식이 한국어뿐이라 CPU 가 영어로 답한
정직한 거절("I'm unable to find the file `payments/legacy.mjs`")을 실패로 적고 있었다.
채점기가 재야 할 것은 답변 언어가 아니라 없다고 말했는가다.

## 2026-09-25 코드 리팩토링 2회차가 고친 것 — 탐침이 표면 변경을 따라가지 않았다

이 회차는 기준선을 다시 재려고 `refuse-absent-file` 을 돌리는 것으로 시작했는데, **첫
시행에서 죽었다.**

```
Error: 배포되지 않는 표면: undefined
    at promptFor (leg-tasks.mjs:117)
    at once (refactor-loop.mjs:88)
```

LEG 3회차가 `promptFor(tools)` 를 `promptFor(task)` 로 바꿨다(과제가 표면을 고르고
프롬프트·도구는 표면이 준다). LEG 탐침만 따라갔고 리팩토링 탐침은 `promptFor(task.tools)`
를 그대로 불렀다. **그 뒤로 이 평가셋은 한 번도 돌지 않았다** — 위 기준선 표는 그 변경
이전의 값이다.

같은 뿌리에서 두 번째 얼굴이 있었다. `edit` 가 같은 날 배포 표면(`KEPT_TOOLS`)으로 들어왔는데
탐침의 실행기에는 `edit` 가 없었다. 모델이 `edit` 를 부르면 `오류: 없는 도구 edit` 이
돌아가 **편집이 적용되지 않은 채** 다음 턴으로 갔고, 채점기의 '고치는 도구' 목록에도
`edit` 가 없어 그 시행이 **부르지도 않은 것과 같은 칸**(`읽기만 함`)에 들어갔다. 즉
모델이 제대로 고쳤는데 탐침이 받지 못하고, 받지 못한 것을 다시 모델 탓으로 적고 있었다.

고친 것 셋. 과제가 `surface: "workspace"` 를 고르고 도구는 `surfaceTools()` 가 채운다.
실행기에 `edit` 를 하네스와 같은 계약으로 넣었다(옛 문자열이 없으면 실패, `replaceAll`
없이 여러 번 나오면 실패 — 되먹임이 배포본과 같아야 한다). 채점기의 편집 도구 목록에
`edit` 를 더했다.

### 재측정 — 고치기 전과 뒤 (각 n=3)

`edit` 를 넣기 전 값은 **탐침을 되살린 직후**(프롬프트 서명만 고친 상태)에 잰 것이다.

| 과제 | 레인 | edit 없던 탐침 | 고친 뒤 |
| --- | --- | --- | --- |
| `rename-across-files` | CPU | 1/3 — `읽기만 함: edit` | **3/3** (턴 4·4·4) |
| `dedupe-block` | CPU | 1/3 — `읽기만 함: read,edit` | 1/3 — `중복이 그대로` · `동작이 깨짐` |
| `flatten-nesting` | CPU | 2/3 — `읽기만 함: edit` | 2/3 (`HTTP 500` 1건) |
| `refuse-absent-file` | CPU | 3/3 | 3/3 |
| `rename-across-files` | GPU | 2/3 | 3/3 |
| `dedupe-block` | GPU | 2/3 | 1/3 — `읽기만 함: read` |
| `flatten-nesting` | GPU | 2/3 | 1/3 (`읽기만 함: read`, `HTTP 500`) |
| `refuse-absent-file` | GPU | 2/3 (`본문 없음` 1건) | 3/3 |

**신호는 합격률이 아니라 실패의 종류다.** `읽기만 함: edit` 이 두 레인에서 완전히
사라졌고, CPU `dedupe-block` 의 실패가 "고치지 않았다"에서 "고쳤는데 모양·동작이
어긋났다"로 바뀌었다 — 이제야 모델을 재고 있다. GPU 편집 과제의 오르내림은 기존에 적힌
흔들림 범위 안이다.

### GPU `본문 없음` 은 제품 결함이 아니라 탐침의 한계다 — 지난 회차 숙제를 닫는다

`refuse-absent-file` 의 GPU 실패를 본문까지 잡아 봤다(n=6, 2026-09-25). 여섯 중 다섯은
본문에 제대로 거절했고, 한 번은 `content` 가 비었는데 **`reasoning` 에 답이 다 있었다.**

```
content=""
reasoning="`payments/legacy.mjs` 파일이 없으므로 리팩토링할 수 없습니다.
           무엇이 없는지 답하고 작업 완료로 마무리합니다."
```

앱은 그 자리를 이미 알린다 — `chat.rs` 가 턴에 사고 기록만 오고 본문이 비면
"모델이 답을 내지 않고 턴을 끝냈습니다. 판단은 사고 기록에 남아 있으니 펼쳐 보시고…"
를 띄운다(`acp_saw_thought`). **사용자에게는 빈 화면이 아니다.** 탐침만 `msg.content` 만
보고 사고 기록을 버리므로 이 한 건이 `본문 없음` 으로 찍혔다.

고치지 않고 남긴다(회차당 한 건). 다음 회차의 첫 일감이고, 고칠 모양은 정해져 있다 —
`본문 없음` 을 "사고 기록에 답이 있음"과 "정말 아무것도 없음"으로 가르는 것이다. 앱이
둘을 다르게 다루므로 채점기도 달라야 한다.

## 기준선 (2026-09-25 코드 리팩토링 2회차, 탐침을 고친 뒤) — **유효한 기준선**

과제 넷 × 3회. 위 표의 '고친 뒤' 열이 그대로 이 표다. 기준선은 목표가 아니라 **바닥**이다.

| 과제 id | GPU 9.7B (n=3) | CPU 20.9B (n=3) |
| --- | --- | --- |
| `rename-across-files` | 3/3 (턴 6·8·6) | 3/3 (턴 4·4·4) |
| `dedupe-block` | 1/3 (턴 7·2·3) | 1/3 (턴 8·5·8) |
| `flatten-nesting` | 1/3 (턴 3·4·3) | 2/3 (턴 4·3·2) |
| `refuse-absent-file` | 3/3 (턴 2·4·2) | 3/3 (턴 2·2·3) |

**위의 옛 표 둘은 배포 표면이 셋·넷이던 때의 값이다.** 지금 표면은 다섯이고 `edit` 가
실제로 실행된다. 같은 축에 놓고 비교하지 않는다.

## 2026-09-25 코드 리팩토링 3회차가 고친 것 — 빈 턴 세 갈래를 한 칸에 넣고 있었다

2회차가 남긴 첫 일감을 그대로 집었다: 채점기가 `본문 없음` 을 "사고 기록에 답이 있음"과
"정말 아무것도 없음"으로 가르는 것.

**먼저 본문을 눈으로 봤다**(4회차 LEG 가 남긴 교훈 — 수치부터 보면 또 프롬프트를 고치러
간다). GPU `refuse-absent-file` n=6 에서 셋이 실패로 찍혔고, **셋 다 사고 기록에 제대로 된
거절이 들어 있었다.** 2회차가 n=6 에서 한 건 잡았던 자리가 이번 표본에서는 셋이다.

```
content=""
reasoning="`payments/legacy.mjs`라는 파일과 폴더가 실제로 존재하지 않습니다.
           요청한 대상이 없으므로 작업을 종료하겠습니다."
```

**CPU 는 여섯 번 모두 본문에 거절을 적었다**(6/6). 한 레인에만 나타나는 결함이고, GPU 만

### 고친 모양 — 앱과 같은 방식으로 가른다

### 고친 모양 — 모르는 것을 한쪽으로 밀지 않고 갈래를 하나 더 둔다

`bash` 는 편집 도구가 아니다. 같은 이름으로 `ls -la` 도 `sed -i` 도 오므로 어느 칸에
넣어도 절반은 거짓이다. 그래서 `EDITORS` 는 계약이 분명한 둘(`write`·`edit`)로 줄이고,
셸만 돈 시행은 **`셸만 돌고 파일이 그대로`** 라는 제 이름을 갖는다. 코드블록 갈래는
`names.length === 0` 조건에서 풀어, 편집 도구를 부르지 않은 모든 자리에서 본다.

| 무엇이 돌았나 | 채점 |
| --- | --- |
| 도구 미호출 + 본문에 코드블록 | `코드블록만 답함(도구 미호출)` (그대로) |
| `write`·`edit` 를 불렀으나 파일이 그대로 | `고치려 했으나 파일이 그대로: <그 도구들>` |
| 읽기 도구만 + 본문에 코드블록 | **`코드블록만 답함(도구는 읽기만: …)`** (새) |
| 읽기 도구 + `bash`, 파일은 그대로 | **`셸만 돌고 파일이 그대로: …`** (새) |
| 정말 읽기만 | `읽기만 함: …` (그대로) |

순서가 뜻이다 — 편집 도구를 불렀으면 본문에 코드블록이 있어도 `고치려 했으나` 다.
시험으로 잠갔다.

| `edit` 가 `오류: oldString 을 파일에서 찾지 못했다` 로 실패하자 두 번 다시 읽고 물러섬. 본문: "실제로 파일을 수정하지 못했습니다. **수정하려는 파일이나 폴더가 없어서** 작업을 수행할 수 없으며…" | 그 문구는 **배포본에 없는 우리말이고**, "파일에서 찾지 못했다"가 *파일이 없다* 로 읽힌다. 다시 시도할 거리(공백·들여쓰기·줄끝까지 맞아야 한다)도 없었다 |

배포본 문구는 `Could not find oldString in the file. It must match exactly, including
whitespace, indentation, and line endings.` 다 — 파일의 존재를 부정하지 않고, 무엇을
고쳐 다시 부를지 말해 준다.

### 고친 모양 — 실패 문구를 배포본에서 읽어 맞춘다

`runTool` 을 `refactor-loop.mjs` 에서 `refactor-tasks.mjs` 로 옮겨 시험이 닿게 하고,
`edit` 실패 넷(`찾지 못함`·`여러 군데`·`같은 문자열`·`빈 oldString`)의 문구를 opencode
1.18.32 실행 파일에서 읽은 그대로 상수로 두었다. `webfetch` 갈래를 더해 스킴 거부도 같은
문구를 쓴다.

**바깥 네트워크만 일부러 배포본과 다르게 둔다.** 무인 회차가 실제로 나가면 측정이 바깥
상태에 묶이고, 리팩토링 과제는 어느 것도 네트워크를 필요로 하지 않는다. 그 자리도 막다른
말이 되지 않도록 쓸 수 있는 도구를 이름으로 짚는다(`read`·`bash`).

표를 놓고 "고쳤다"고 적었을 것이다. 배포 경로에는 계획 턴의 `cannot_do` 가 앞에 있어 "할 일이
없다"가 단계로 서지 않는데, 탐침에는 그 턴이 없다. 그래서 같은 조건이 **끝난 일과 못 할 일까지
다시 떠밀었다**(20시행에 40회 — 매 시행 상한까지).

### 고친 모양 — 본문이 빈 턴만 다시 보낸다

`isUnstartedTurn` 하나가 정한다: 도구도 없고 **본문도 빈** 턴. 이것이 앱에서 "끊김"으로 보이는
모양이고(`chat.rs::note_silent_turn`), GPU `읽기만 함: read` 가 정확히 그 모양이다 — 고친 코드를
사고 기록에 코드 블록으로 적고 본문 없이 턴을 닫는다. 정직한 거절은 본문이 있으므로 이 조건에
걸리지 않는다. 상한은 배포본 `MAX_STEP_RETRIES` 에서 읽어 맞춘다(시험이 소스에서 읽어 비교).
`NO_NUDGE=1` 이 이 경로 없이 재는 비교용 스위치다.

### 재측정 — 고치기 전과 뒤 (전부 오늘 같은 코드에서 잰 값이다)

| 과제 | 레인 | 고치기 전 | 고친 뒤 | 실패 종류 |
| --- | --- | --- | --- | --- |
| `flatten-nesting` | GPU (n=20) | 16/20 | **19/20** | 전: `읽기만 함: read` 4. 후: `중첩이 그대로` 1 |
| `flatten-nesting` | CPU (n=20) | 19/20 | 18/20 | 전: `코드블록만 답함(도구는 읽기만: read)` 1. 후: `동작이 깨짐` 1 외 1 |
| `refuse-absent-file` | GPU (n=10) | 6/6(3회차) | **10/10** | 없음 |
| `refuse-absent-file` | CPU (n=10) | 6/6(3회차) | **10/10** | 없음 |

**신호는 합격률이 아니라 실패 종류다.** 7회차가 넘긴 `읽기만 함: read` 가 GPU 20시행에서
4건 → **0건**이 됐고, 되돌리면(`NO_NUDGE=1`) 다시 나온다.

**CPU 는 이 경로가 한 번도 불리지 않았다**(다시 보냄 0회, 두 과제 모두). 이 레인은 본문을
비우고 끝내는 일이 없어서 조건에 걸리지 않는다. 그러니 CPU 의 19/20 → 18/20 은 **같은 코드
경로를 두 번 잰 흔들림**이지 이 변경의 효과가 아니다 — 시소가 없다는 것이 이 줄의 뜻이다.

비용: GPU 턴이 3~7 에서 3~8 로 늘고 20시행에 19회 다시 보냈다. 통과이되 비싼 자리다.

## 다음 회차가 이어받을 것 (2026-09-28 코드 리팩토링 8회차 기준)

- **탐침과 제품의 차이를 더 가른다.** 이번 것은 하나였고 실제로 있었다. 남은 큰 차이는
  탐침에 **계획 턴이 없다**는 것이다 — 배포 경로는 계획을 세우고 단계마다 도구 하나만 열지만
  탐침은 다섯을 한꺼번에 연다. 이 종류를 계획 경로로도 재려면 `plan-eval` 쪽에 리팩토링
  과제를 세워야 하고, 그것은 한 회차짜리 일이다.
- GPU `중첩이 그대로` 1건, CPU `동작이 깨짐` 1건. 둘 다 1회짜리라 흔들림과 구별되지 않는다.
- `dedupe-block` 은 5회차 이후 다시 재지 않았다. GPU 3~4/6 이 여전히 가장 낮은 줄이다.
- 턴 상한 8 에 GPU 가 이번에도 닿았다(4회차부터 다섯 번째 미결). 다시 보냄이 턴을 쓰므로
  이제 더 자주 닿는다 — 올릴지 정할 때가 됐다.
