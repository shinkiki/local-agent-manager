## 변경 전에 세운 가설

앞선 원본 세션 ses_f23842cd6와 반복 탐침에서 노션 저장을 제목에 적고 도구는
write로 선택했다. 플러그인 이름의 한글 별칭은 있어도 작업 뜻은 영문 설명이라
생성·수정 의미가 충분히 연결되지 않을 수 있다. 이를 경로 지시 없이 확인한다.

후보는 기존 색인의 두 설명 앞에 아래 뜻풀이만 덧붙인다. 영문 설명과 소유자,
도구 이름·개수·순서를 그대로 유지하며 새 도구나 요청별 필터를 넣지 않는다.

- notion-create-pages: 노션 페이지 생성: 제목과 본문으로 새 페이지를 만든다.
- notion-update-page: 노션 페이지 수정: 기존 페이지의 속성이나 본문을 바꾼다.

나머지 도구에 금지·우선순위를 붙이지 않는다. 제품 고리(단계당 1개, 초안 폐기 보호,
두 번 되묻기)와 스키마도 그대로다. 원래 요청의 특정 React 내용은 뜻풀이에 없다.

## 측정 설계와 재현

web-to-notion 한 과제에서 guard 대 gloss 각각 20회, 공유 UUID 요청 표식으로
AB/BA 교대한다. UUID는 모델 난수 seed가 아니다. n≤6 결과로 설정을 선택하지 않는다.
합격률 외에 노션 누락, write 대체, 조기 즉답, 직접 호출, 잘못된 거절을 분류한다.
채택 여부는 반대 방향 과제와 수정 후 실기기 확인까지 포함해서 판단한다.

실측 시작 전 새 후보의 초안 보호가 빠진 것을 회귀 시험이 잡았고 바로잡았다.
GPU는 그 시험이 통과한 뒤 시작했으므로 잘못된 고리로 얻은 측정값은 없다.

~~~powershell
$env:REPEATS='20'
$env:ONLY_TASK='web-to-notion'
$env:VARIANTS='guard,gloss'
$env:TRACE_FILE=Join-Path $env:TEMP 'plan-gloss.jsonl'
node local-llm-dev/plan-eval/index-probe.mjs qwen3.5-gpu-128k:latest
~~~

원시 기록은 %TEMP%/agent-manager-plan-consistency-20260926-round3/
아래 gpu-gloss.jsonl과 manifest.json에 저장한다. .tuning에는 측정 로그를 쓰지 않는다.

반복한 후 빈 계획을 즉답으로 끝냈다. 어휘 부족과 제어 도구 선택 실패를 구분해야 한다.

다음 분리 가설은 초안 상태에서 항상 거절되는 insert_step이 계획 도구 목록에 노출된
자리다. 단, 같은 계획 agent를 실행 중 재계획에도 쓰므로 전역으로 숨기면 그쪽을
깨뜨릴 수 있다. 이번에는 이 경로를 바꾸지 않았다. 상태별 도구 노출 또는 초안 삽입
의미를 명확히 하는 후보를 제품 고리와 맞춰 별도로 측정해야 한다.

제품 수정은 채택하지 않았으므로 이번 회차의 새 실기기 수정 검증은 없다. 개발 백엔드도

바꾼 실험이므로 어느 문장이 영향을 줬는지는 분리되지 않는다. 노션 생성까지 포함한
전체 후보의 채택 근거로 삼지 않고, 수정 뜻풀이 단독 비교는 별도 가설로 남긴다.

기록한 의도와 수락된 계획을 혼동하는 문제를 다음 측정에서 구분할 근거다.
