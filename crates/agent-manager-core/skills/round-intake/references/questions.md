# 문진표 — 6묶음

한 번에 묶어 낸다. 각 줄의 **잰 값**을 질문 옆에 붙이고, 답이 없으면 **기본값**으로 진행한 뒤
목표 `notes` 에 "추천값으로 정함"이라고 적는다.

## 1. 자원·병렬

온보딩 카드로 들어온 회차는 이 묶음을 **통째로 건너뛴다**(카드가 이미 받았다).

| 질문 | 먼저 잰 값 | 기본값 |
|---|---|---|
| 이 회차를 동시에 여러 건 돌릴까요 | `get_usage_budget` 의 `throughput.rounds[].maxRuns` / `recommendedMaxRuns` | 끔 |
| 동시 몇 건 | 위 추천치. 없으면 계정 풀의 `netHeadroomPercent` 로 가늠 | 추천치, 없으면 3 |
| 레인 풀 경로 | 저장소 루트 아래 관행 | `.rounds` |
| 레인 작업브랜치 | `get_project_git_overview` 의 기본 브랜치 | `origin/main` |
| 반영 방식 | 원격 유무 | 레인 브랜치에 커밋만 |
| 분할 기준 | 목표가 항목 목록인지 경로 묶음인지 | 항목 점유 |
| 같은 자원을 쓰는 회차가 이미 있는데 어떻게 나눌까요 | `get_live_chats`·`list_scheduled_runs` 에서 겹침을 찾았을 때만 묻는다 | 시간을 갈라 둔다 |

병렬을 켜면 회차 스킬은 `parallel-round-lanes` 를 따르고 지시문 앞머리에 `## 병렬 실행` 블록을 둔다.
켠 채로 1건은 병렬이 아니다 — 그때는 끈 것으로 적는다.

## 2. 품질 관문

| 질문 | 먼저 잰 값 | 기본값 |
|---|---|---|
| 반영 전에 코드리뷰를 걸까요 | 저장소에 리뷰 절차가 적혀 있는지 | **안 함** |
| (건다면) 어느 수준 | — | 변경분 리뷰 1회, 반영 직전 |
| 보안 리뷰를 걸까요 | 목표가 자격증명·외부 전송에 닿는지 | 안 함 |
| 커밋 전 무엇이 통과해야 하나요 | `AGENTS.md`·`CLAUDE.md` 의 검증 명령 | 저장소 절차 그대로 |

기본이 "안 함"인 이유는 비용이다. 회차 보고의 실패 종류에 리뷰로 걸렀을 결함이 쌓이면 그때
`decisions` 로 올려 켠다. 설계가 미리 켜 두지 않는다.

## 3. 반영 정책

| 질문 | 먼저 잰 값 | 기본값 |
|---|---|---|
| 어디까지 밀까요 (커밋만 / 푸시 / PR) | 원격 유무, 보호 브랜치 | 커밋만 |
| 무엇을 보면 되돌리나요 | — | 검증 실패 시 그 회차 변경 전부 |
| 머지는 누가 하나요 | — | 사람 |

푸시·PR 은 바깥에 남는 행위다. 기본값으로 밀지 않는다.

## 4. 멈춤·완료 조건

| 질문 | 먼저 잰 값 | 기본값 |
|---|---|---|
| 언제 이 회차가 끝났다고 보나요 | 지난 회차의 `completionCondition` | 없음(무기한) |
| 연속 실패하면 멈출까요 | `list_round_reports` 의 최근 `outcome` | 3회 연속 fail 이면 보고만 하고 멈춤 |

## 5. 비용 상한

| 질문 | 먼저 잰 값 | 기본값 |
|---|---|---|
| 회차당 상한을 둘까요 | `get_usage_budget` 의 `costs.perProvider[].percentPerRun` | 없음 |
| 주기 | 비슷한 회차의 `cadenceMinutes` | auto |

상한을 집행(`enforceCeiling`)하면 넘는 회차가 아예 뜨지 않는다. 재 본 비용이 없을 때는 상한을
걸지 않는다 — 숫자 없이 건 상한은 회차를 조용히 멈춘다.

## 6. 사람이 정할 자리

| 질문 | 기본값 |
|---|---|
| 회차가 손대면 안 되는 것은 무엇인가요 | 모델 교체, 능력 추가(아웃바운드 네트워크 등), 사용자 문서, 운영 앱 |

여기 적힌 것은 회차가 하지 않고 `record_round_report` 의 `decisions` 로 올린다.
